## 2026-10-13 — Instalador de Evolution: soporte Apache para producción (#9991239)

**Qué estaba roto.** `deploy/provision/install.sh` solo sabía configurar nginx en su paso 30, y
producción corre Apache2. En prod el script se detenía ahí ("No pude detectar el vhost de
MegaISP") **antes** del paso 40, que es el que arranca Evolution en PM2 y la deja con arranque en
boot: Evolution quedaba compilada pero sin correr. Además la guarda anti-dev sugería
`ALLOW_PROVISION=1 sudo bash …`, que no funciona (sudo con `env_reset` descarta la variable).

**Qué cambia** (solo scripts y documentación; nada se ejecutó en producción):
- `lib/30-apache.sh` — `ProxyPass /evolution/ → 127.0.0.1:8080` en todos los `<VirtualHost>`
  habilitados con `DocumentRoot` exacto `<MEGAISP_ROOT>/public` (el legacy `/var/www/MEGANET`
  queda fuera). WebSocket con `upgrade=websocket` en Apache ≥ 2.4.47, o `RewriteRule [P]` a
  `ws://` + `mod_proxy_wstunnel` en versiones anteriores. Respaldo con fecha; si `apache2ctl
  configtest` falla restaura los vhosts, deshabilita los módulos que habilitó y no recarga.
- `lib/30-proxy.sh` — elige nginx o Apache por el servicio activo (`WEB_SERVER` para forzar;
  aborta si ambos están activos) y ofrece `SKIP_WEB_PROXY=1` como plan B: MegaISP habla con
  Evolution por `127.0.0.1:8080`, así que funciona aunque el proxy no se publique.
- `lib/30-nginx.sh` no se tocó; `install.sh` llama al despachador.
- Texto de la guarda → `sudo env ALLOW_PROVISION=1 bash …`.
- `README.md` — overrides nuevos y **runbook de PROD** paso a paso, empezando por la entrada de
  bitácora PREVIA que exige CLAUDE.md.
- `tests/test-30-apache.sh` — prueba con Apache simulado.

**Cómo se verificó.** Dev no tiene Apache ni root para instalarlo, así que la ruta Apache se probó
con un Apache **simulado** (vhosts temporales + shims de `apache2ctl`/`a2enmod`/`a2dismod`/
`systemctl`), con `set -euo pipefail` como el instalador real: **33/33** casos — inyección en
`:80` y `:443` (incluido `DocumentRoot` con comillas y barra final), legacy intacto, symlink de
`sites-enabled` preservado, respaldo idéntico al original, segunda corrida sin cambios,
`configtest` fallido → vhost restaurado byte a byte + módulos deshabilitados + sin recarga, Apache
2.4.38 → variante `RewriteRule`, detección del servidor web y vhost inexistente. La ruta nginx se
re-probó a través del despachador (inyecta, `nginx -t`, recarga). `bash -n` limpio en todo.

**Lo que NO se pudo verificar aquí:** que el Apache real de prod acepte la configuración. La
red de seguridad es el `configtest` + reversión automática, y el plan B `SKIP_WEB_PROXY=1`.

**Estado.** Rama `circuito/item-9991239-evolution-instalador-apache`, sin mergear. Nivel B: el
merge necesita el visto bueno de Irving. Después del merge y de un release que lo lleve a prod,
alguien con root en .108 sigue el runbook del README (con su bitácora previa).

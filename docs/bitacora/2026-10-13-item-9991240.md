## 2026-10-13 — WhatsApp: avisar claro cuando Evolution API no está instalada o no responde (#9991240)

**Qué se veía roto.** En producción Evolution API no está instalada. La pantalla de Líneas no lo
decía en ningún lado: crear una línea respondía 201 aunque Evolution no existiera (el error solo
quedaba en el log), al abrir la pantalla salía una ventana de "No se pudo sincronizar" por cada
línea, y el problema real aparecía tarde, al pedir el QR, sin decir que faltaba Evolution.

**Qué cambia**
- `EvolutionApiService::salud()` — una sola petición a `/instance/fetchInstances` con la llave
  (connect 2 s / total 4 s), cacheada 30 s. Estados: `ok`, `simulado` (WHATSAPP_FAKE),
  `sin_configurar`, `no_responde`, `llave_rechazada`, `error`. Nunca devuelve la llave.
- `GET /whatsapp/api/evolution/salud` (`?fresco=1` salta la caché). Mismo grupo y mismos permisos
  que el resto de las Líneas (hoy: admin / desarrollador / super-admin); no se tocó
  `config/route_permission.php`.
- `store()` sigue guardando la línea — decisión de esta sesión: bloquear la creación rompería el
  flujo de una línea que va a usar Meta (no necesita Evolution), y «Conectar / Ver QR» ya recrea la
  instancia on-demand (`ensureInstanceExists`). Lo que cambia es que la respuesta trae
  `evolution: {ok, mensaje, detalle}`: falla de conexión → "no está instalada o no responde";
  Evolution contesta con error → "rechazó crearla"; "already in use" cuenta como éxito.
- Pantalla de Líneas: banner rojo con el diagnóstico y el detalle técnico plegado + botón "Revisar
  de nuevo"; solo aparece si alguna línea usa Evolution (o aún no hay líneas). Al crear una línea que
  Evolution no pudo crear sale un aviso amarillo de 10 s. Con Evolution caída ya no se dispara el
  sync automático (era la cascada de ventanas de error) y el sync automático nunca abre ventanas.

**Cómo se verificó** (tinker sobre la BD de dev cargando las clases de la rama, `store()` dentro de
una transacción con rollback; nunca se creó una instancia en la Evolution real de dev):

| Caso | Resultado |
|---|---|
| Evolution real de dev | `ok` |
| URL a un puerto cerrado | `no_responde` |
| Llave inválida (en memoria) | `llave_rechazada` (HTTP 401) |
| URL vacía | `sin_configurar` |
| WHATSAPP_FAKE | `simulado` |
| ¿La respuesta de salud contiene la llave? | no |
| `store()` con Evolution caída | 201 + `evolution.ok=false` con el mensaje |
| `store()` con 403 "already in use" (Http::fake) | 201 + `ok=true` |
| `store()` con 401 de Evolution (Http::fake) | 201 + `ok=false` "rechazó crearla" |
| `store()` en modo fake | 201 + `ok=true` |
| Filas de prueba que quedaron | 0 |
